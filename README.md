Reflection 1
Selama mengerjakan fitur Edit dan Delete ini, saya belajar banyak tentang bagaimana menulis kode yang tidak hanya asal jalan, tapi juga rapi dan mudah dimengerti orang lain (prinsip Clean Code). Salah satu yang saya terapkan adalah pemberian nama variabel dan fungsi yang jelas. Dulu mungkin saya sering pakai nama singkat seperti del atau u, tapi sekarang saya pakai delete dan update supaya siapa pun yang membaca kode saya langsung tahu fungsinya tanpa harus menebak-nebak. Ini sangat membantu terutama saat kita bekerja dalam tim.

Selain itu, saya belajar untuk membuat setiap fungsi menjadi kecil dan fokus pada satu tugas saja (SOP - Single Responsibility Principle). Misalnya, fungsi untuk menghapus produk ya tugasnya cuma menghapus saja, lalu mengarahkan kembali ke halaman daftar. Saya juga membiasakan diri untuk menjaga data tetap aman dengan menggunakan akses private pada penyimpanan data di repository. Jadi, data kita tidak bisa diacak-acak sembarangan dari luar tanpa melalui jalur yang sudah disediakan.

Meskipun sudah mencoba menerapkan kode yang bersih, saya menyadari masih ada beberapa kekurangan yang bisa diperbaiki. Contohnya, aplikasi saya masih agak "rapuh" kalau ada orang iseng yang memasukkan ID produk sembarangan di URL. Seharusnya, saya menambahkan pengecekan agar kalau produknya tidak ketemu, aplikasi memberikan pesan yang jelas atau kembali ke halaman utama, bukan malah error. Ini penting untuk kenyamanan pengguna dan keamanan aplikasi itu sendiri.

Ke depannya, saya juga ingin mencoba menambahkan validasi input yang lebih kuat. Saat ini, pengguna masih bisa memasukkan jumlah produk yang minus atau nama produk yang kosong. Dengan menambahkan validasi seperti @Min atau @NotBlank di bagian Model, data yang masuk ke sistem jadi lebih terjamin kebenarannya. Belajar Clean Code ternyata bukan sekali jadi, tapi proses terus-menerus untuk membuat kode kita semakin berkualitas setiap harinya.
